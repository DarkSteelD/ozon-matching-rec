# E-CUP 2026 — матчинг товаров Ozon (Задача 1)

Командный репозиторий задачи «Матчинг товаров» соревнования Ozon E-CUP 2026
(Students): идентификация одинаковых товаров по **текстовой** информации из
карточек (дедупликация карточек). ODS-слаг: `e-cup-2026-matching`.

## Ключевые факты

Зафиксированы 2026-08-09 по правилам и странице трека (задачи открылись
2026-08-10 — всё из раздела «Открытые вопросы» перепроверить по странице задачи).

| Параметр | Значение |
| --- | --- |
| Формат решения | код-контейнер |
| Входные данные | текстовая информация карточек — **без изображений** (в отличие от матчинга-2024: названия + атрибуты + image embeddings) |
| Метрика | фиксируется со страницы задачи |
| Окно посылок | по `2026-08-30 23:59 MSK`, 5 сабмитов/день, сброс 00:00 MSK |
| Финальные решения | выбрать ≤2 до `2026-08-31 12:00 MSK`, иначе платформа выберет сама |

Правило, влияющее на дизайн: переразметка данных LLM разрешена, но **только
моделями с открытой лицензией**; проприетарные LLM запрещены. Код обучения и
разметки должен быть воспроизводимым.

## Открытые вопросы первого дня

1. **Даны ли candidate pairs.** В 2024 пары были даны (задача = классификация
   пары). Формулировка 2026 «идентифицировать одинаковые товары» — если пары не
   даны, пайплайн другой: retrieval → rerank → кластеризация.
2. **Контейнерный envelope** — CPU, RAM, GPU/VRAM, лимит времени инференса.
   Определяет размер модели арифметикой, до него дизайн не фиксировать.
3. **Метрика** — прецедент 2024: скор считался **по категориям** (см.
   `members/darksteeld/reports/PUBLISHED_SOLUTIONS.md`), оптимизировать
   per-category, не глобально, если это подтвердится.

## Структура репозитория

```text
data/
  raw/                    # единая неизменяемая копия данных задачи, не хранится в Git
members/
  darksteeld/             # рабочая область участника: evidence base исследований, далее код
  <github-name>/          # рабочая область следующего участника
validation/               # командный контракт валидации — фиксируется после пиновки метрики и данных
```

Evidence base перенесена из мета-исследования `ozon-ecup-2026`:
`members/darksteeld/reports/FAMILY_MATCHING.md` — что реально двигает скор в
матчинге (Shopee, Amazon ESCI, WDC, Ditto и др., с числами), плюс общие отчёты
кампании (`00_SUMMARY.md`, `PRIOR_EDITIONS.md`, `PUBLISHED_SOLUTIONS.md`,
`OZON_NATIVE.md`).

## Правила работы команды

1. Не коммитить исходные данные, модели, секреты и файлы отправок.
2. Репозиторий приватный, публичных зеркал нет (правила соревнования, §2.12).
3. Создавать отдельную ветку для каждой гипотезы или задачи; в pull request
   описывать схему валидации и изменение метрики.
4. Переносить полезную логику из ноутбуков в `src/` своей рабочей области.
5. Оракульный потолок лейна и noise floor канала оценки измеряются **до**
   строительства лейна (см. `members/darksteeld/CAMPAIGN_RULES.md`).
6. Контракт валидации фиксируется всей командой в `validation/` и не меняется
   под конкретную модель.
