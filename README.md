# E-CUP 2026 — матчинг товаров Ozon (Задача 1)

Командный репозиторий задачи «Матчинг товаров» соревнования Ozon E-CUP 2026
(Students): идентификация одинаковых товаров по **текстовой** информации из
карточек (дедупликация карточек). ODS-слаг: `e-cup-2026-matching`.

## Ключевые факты

Базовые факты зафиксированы 2026-08-09 по правилам и странице трека; данные и
baseline сняты со страницы задачи **2026-08-13** `[V]`.

| Параметр | Значение |
| --- | --- |
| Формат решения | код-контейнер |
| Входные данные | текстовая информация карточек — **без изображений** (в отличие от матчинга-2024: названия + атрибуты + image embeddings) |
| Постановка | **кандидатные пары даны**: на вход решению подаются новые товары и их пары; классификация пары, retrieval не нужен |
| Лимит исполнения | **20 минут** на полный прогон решения (baseline укладывается в 18.5) |
| Метрика | на странице данных не указана — зафиксировать с ЛБ/правил задачи |
| Окно посылок | по `2026-08-30 23:59 MSK`, 5 сабмитов/день, сброс 00:00 MSK |
| Финальные решения | выбрать ≤2 до `2026-08-31 12:00 MSK`, иначе платформа выберет сама |

Правило, влияющее на дизайн: переразметка данных LLM разрешена, но **только
моделями с открытой лицензией**; проприетарные LLM запрещены. Код обучения и
разметки должен быть воспроизводимым.

## Данные `[V 2026-08-13, страница задачи]`

| Файл | Размер | Содержимое |
| --- | --- | --- |
| `matches.parquet` | 4.1 MB | пары товаров с **ручной** разметкой |
| `matches_llm.parquet` | 104.7 MB | пары товаров с разметкой **LLM** |
| `items.parquet` | 4.1 GB | полные данные о товарах |
| `items_human.parquet` | 214.2 MB | подмножество товаров, встречающихся только в ручной разметке |

Глоссарий `matches*.parquet`: `id1`, `id2` — идентификаторы товаров пары;
`target` — метка совпадения: **0/1 в ручной разметке, от 0 до 1 в LLM-разметке**
(мягкие метки — кандидат на дистилляцию/взвешивание, но проверить их сдвиг
относительно ручных).

Глоссарий `items*.parquet`: `id`, `name` (название), `attributes` (свернутый
JSON атрибутов текстом), `category` (категория товара).

Все товары `items_human.parquet` содержатся в `items.parquet`; эта пара файлов
эмулирует прогон решения локально. **Суммарный объём тестовых данных сопоставим
с `matches.parquet` + `items_human.parquet`** — т.е. тест по масштабу равен
ручной разметке, и в тестовых данных о товарах есть только участники пар.

## Baseline и временной envelope `[V 2026-08-13]`

- `matching-baseline-submit.zip` (1.2 GB) — валидное решение на
  `cross-encoder/ms-marco-MiniLM-L12-v2` (HuggingFace); полный прогон
  **18.5 минут при лимите 20** — это ориентир максимально допустимой тяжести
  модели: MiniLM-L12 cross-encoder ≈ потолок по времени.
- `matching-baseline-lightweight.zip` (19.6 KB) — тот же код без модели, для
  отладки.
- **Все модели и артефакты должны быть включены в архив и/или образ** решения.

`OZON_NATIVE.md`).

## Правила работы команды

1. Не коммитить исходные данные, модели, секреты и файлы отправок.
2. Репозиторий приватный, публичных зеркал нет (правила соревнования, §2.12).
3. Создавать отдельную ветку для каждой гипотезы или задачи; в pull request
   описывать схему валидации и изменение метрики.
4. Переносить полезную логику из ноутбуков в `src/` своей рабочей области.
5. Оракульный потолок лейна и noise floor канала оценки измеряются **до**
   строительства лейна (см. `members/darksteeld/CAMPAIGN_RULES.md`).
6. Контракт валидации фиксируется всей командой в `validation/` и не меняется
   под конкретную модель.
