# Эксперименты: контракт запуска

Единый способ «закоммитил код — получил цифру в общей таблице». Раннер
(`validation/ops/train.py`) не знает про модели, он знает только контракт;
всё остальное — твой код.

## Как завести эксперимент

Скопируй шаблон в свою рабочую область:

```bash
cp -r validation/ops/experiment_template members/<твой-ник>/experiments/<имя-эксперимента>
```

Внутри два файла: `experiment.json` (манифест) и `train.py` (код). Правь
`predict_fold` в `train.py` — остальное шаблон делает сам: берёт канонический
список объектов фолда, соблюдает порядок строк и формат колонок трека.

`experiment.json`:

```json
{
  "description": "LightGBM на recency-окнах 7/14/30",
  "entry": "python train.py",
  "requirements": ["lightgbm==4.5.0"],
  "gpus": 1,
  "timeout_min": 120
}
```

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `entry` | да | команда запуска, выполняется из каталога эксперимента |
| `description` | нет | попадёт в заметку к результату |
| `requirements` | нет | ставится в venv, кэшируемый по хешу списка |
| `gpus` | нет | сколько карт нужно; раннер выдаёт их через `CUDA_VISIBLE_DEVICES` |
| `timeout_min` | нет | по умолчанию 180, дальше процесс снимается |

## Что получает твой скрипт

```
<entry> --out-dir <куда писать> --data-dir <repo>/data/raw \
        --repo <repo> --folds fold_01,fold_02,fold_03,fold_04
```

Он обязан записать `<out-dir>/<fold>.csv` на каждый фолд. Колонки и тип
предсказания объявлены в `ops_config.json` (`prediction_columns`,
`prediction_dtype`) — шаблон читает их оттуда, руками дублировать не надо.

Порядок строк обязан совпадать с каноническим файлом фолда
(`validation/targets/<fold>.csv`).
Шаблон берёт его именно оттуда, поэтому не сортируй и не перемешивай.

### Артефакт решения

Если раннер передал `--submission-dir`, туда можно положить готовое решение для
отправки на ODS: CSV предсказаний на реальном тесте либо zip-контейнер. Оркестратор
заберёт его в реестр, и эксперимент станет доступен для отправки кнопкой `/send`
в телеграме.

Предсказания по фолдам решением **не являются**: фолды меряют качество, а на ODS
уезжает другой файл. Флаг опциональный — эксперимент вправе его игнорировать, тогда
метрика в таблице будет, а отправить его будет нечем.

**Главное правило:** предсказывая фолд K, не используй его данные — ни для
обучения, ни для подбора порогов, ни для отбора признаков. Обучайся на
остальных фолдах. Это единственное, что раннер проверить не может.

## Запуск

```bash
python validation/ops/train.py --list                       # какие эксперименты видит
python validation/ops/train.py --member ник --experiment имя --dry-run
python validation/ops/train.py --member ник --experiment имя
python validation/ops/train.py --member ник --experiment имя --gpus 0,1
```

`--dry-run` пишет во временный каталог и **не** регистрирует результат — этим
проверяют, что код вообще работает. Без него предсказания ложатся в
`validation/predictions/<ник>/<имя>/`, сразу считается метрика, обновляется
`validation/leaderboard.csv`, результат уезжает в общую таблицу и в телеграм.

Ту же работу делает общая джоба: если ты просто запушил каталог с
предсказаниями, она подхватит его сама и посчитает.

## Частые грабли

- **«expected columns \[...\], found \[...\]»** — не те колонки. Смотри
  `prediction_columns` в `ops_config.json`; лишние поля вроде `category` в файл
  предсказаний не кладутся.
- **«invalid integer value»** — на quality вердикты жёсткие, `0`/`1`, а не `0.0`.
- **«не нашёл канонический файл фолда»** — не собраны цели:
  `make validation-targets`.
- **эксперимент не появился в `--list`** — нет `experiment.json` либо каталог
  лежит не в `members/<ник>/experiments/<имя>/`.
- **новое имя на каждое изменение логики.** Повтор имени намеренно
  перезаписывает прошлый результат — так задумано, но переписать чужой
  результат этим тоже можно.

## Черновики

Имя, начинающееся с подчёркивания (`_проба`), общая джоба игнорирует: ни
скоринга, ни коммита, ни сообщения в телеграм. Это способ подержать сырое в
`validation/predictions/` и не засветить его в командной таблице. Для проверки
самого кода лучше `--dry-run` — он вообще ничего не кладёт в репозиторий.
