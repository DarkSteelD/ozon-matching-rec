# Командный контракт валидации — e-cup-2026-matching

Этот каталог — командный контракт сравнения независимых исследований. Фолды
заморожены; их смена — новая версия валидации и отдельное командное решение
(`fold_spec_version` в каждом результате). Не менять фолды под конкретную
модель.

## Замороженные фолды: grouped K=4 по компонентам связности

`folds.json` — спецификация v1. Единица группировки — **компонента связности
графа ручных пар** (`matches.parquet`: вершина = товар, ребро = размеченная
пара, любой label). Товар никогда не попадает в два фолда: иначе модель,
видевшая товар в train-фолде (embedding, статистики, память энкодера), получает
утечку на eval-фолде. Обоснование и структура графа — в
`../members/darksteeld/reports/DATA_EDA.md` §2: 345 654 компоненты, 95.7% —
одиночные пары, максимум 31 пара, поэтому группировка почти бесплатна и фолды
сбалансированы автоматически.

Детеминированное построение без RNG: ключ компоненты = минимальный id товара в
ней; `fold = sha256(seed:key) mod 4`, seed зафиксирован в `folds.json`.
Построение: `make validation-targets` (нужны `data/raw/matches.parquet` и
`data/raw/items_human.parquet`). Файлы целей локальны и игнорируются Git —
метки не коммитятся; коммитятся только билдер и SHA256-пины, которые
`evaluate.py` сверяет перед каждым скорингом.

## Метрика

PR-AUC = `average_precision_score` (собственная numpy-реализация в
`evaluate.py`, проверена на тождественность sklearn до 1e-12, включая ties).
Официальная метрика — `total_prauc` в API лидерборда ODS.

**Открытый вопрос агрегации.** Слаг «total» намекает на пул по всем парам, но
прецедент матчинга-2024 — макро по категориям. Пока вопрос не закрыт, evaluate
считает обе агрегации в каждом результате:

- `mean_prauc` — среднее четырёх фолдовых PR-AUC. **Первичный ключ местного
  лидерборда** (устойчивее пула к межфолдовой калибровке).
- `pooled_prauc` — PR-AUC по объединению OOF-предсказаний всех фолдов (форма
  «total», если метрика пул).
- `macro_cat_prauc` — макро-среднее PR-AUC по 20 категориям на объединении OOF
  (форма 2024 года); в JSON также `per_category` и `worst_category`, prior по
  категориям 0.073–0.562.

Наблюдаемый разброс между фолдами у бескалибровочных бейзлайнов ~0.003–0.007
PR-AUC — сравнивайте эксперименты по парным пофолдовым дельтам, а не по одному
числу (ship gate: `../members/darksteeld/CAMPAIGN_RULES.md`).

## Контракт предсказаний

Один файл на фолд, канонический порядок пар = порядок в файле целей
(сортировка по `id1, id2`; билдер воспроизводит его байт-в-байт):

```text
validation/predictions/<member>/<experiment>/
  fold_01.csv  fold_02.csv  fold_03.csv  fold_04.csv
```

Колонки строго `id1,id2,predict`; предсказания конечные числа (вероятность или
любой монотонный скор — PR-AUC инвариантен к монотонным преобразованиям);
дубликаты пар запрещены. Формат сознательно совпадает с выходом контейнера
решения (`id1,id2,predict` CSV) — файл сабмита и файл валидации порождаются
одним кодом.

Скоринг и регистрация эксперимента (из корня репозитория):

```bash
make validation-targets            # один раз: построить локальные цели
make score MEMBER=darksteeld EXPERIMENT=name_tfidf_cos \
  NOTES="char 3-5gram TF-IDF cosine of names"
```

`make` использует `.venv/bin/python` репозитория, если он есть, иначе
`python3`; переопределение: `make score PY=/path/to/python ...`. Зависимости:
`numpy` (evaluate), `polars` (builder).

После сабмита той же модели на ODS зафиксировать наблюдаемый публичный скор:

```bash
make score MEMBER=... EXPERIMENT=... PUBLIC_PRAUC=0.1334 NOTES="..."
```

`public_rank` — ранг только среди командных экспериментов с записанным
публичным скором; `public_delta = public_prauc − mean_prauc`. Публичные скоры —
диагностика пайплайна, не сигнал для подбора фолдов, калибровки или весов
(CAMPAIGN_RULES #2, #12b): каждый порог отбора кандидатов номинируется в
CV-единицах.

Результат пишется в `validation/results/<member>/<experiment>.json`,
лидерборд перегенерируется в `leaderboard.csv` + GitHub-читаемый
`leaderboard.md` (сортировка по убыванию `mean_prauc`). Коммитить JSON и оба
файла лидерборда вместе с кодом эксперимента; сырые предсказания остаются
локальными. Пересобрать таблицу после merge: `make leaderboard`; только
Markdown из CSV: `make leaderboard-md`.

Новая логика/фичи/гиперпараметры → новое имя эксперимента; повторное имя
намеренно перезаписывает результат.
