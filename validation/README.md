# Командный контракт валидации — будет зафиксирован после пиновки задачи

Метрика и формат данных задачи фиксируются со страницы ODS
(`e-cup-2026-matching`). До этого контракт не пишем: фолды, нарезанные до
понимания метрики, пришлось бы менять, а смена фолдов = новая версия валидации
и отдельное командное решение.

Принципы, которые контракт обязан соблюдать (перенесены из
`../members/darksteeld/CAMPAIGN_RULES.md` — каждое оплачено измеренным провалом):

1. Замороженные фолды: не менять под конкретную модель.
2. Noise floor канала оценки измеряется до чтения любых дельт из него
   (1–2 идентичных ресабмита из дневного лимита в первые дни).
3. Ship gate из четырёх условий: pooled-улучшение ≥ noise floor, ни один блок
   не хуже допуска, worst-case не взрывается, большинство фолдов улучшается.
4. Оракульный потолок лейна считается до строительства лейна.
5. Public LB — диагностика, не сигнал для подбора фолдов/калибровки/весов.

Референс устройства контракта: `validation/` в командном репозитории
`ozon-ltv` (фолды в `folds.json`, результаты в `results/<member>/*.json`,
общий leaderboard, `make score`).
