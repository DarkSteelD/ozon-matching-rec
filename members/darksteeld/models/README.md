# Веса RuModernBERT

Всё через git LFS. После клона: `git lfs pull`, иначе вместо весов будут
текстовые указатели.

## `rumodernbert_llm_pretrain/`

RuModernBERT-base после одной эпохи BCE на 11.19M мягких пар от LLM, до всякого
дообучения на ручной разметке. Голова на два логита, скор — разность
`logit1 - logit0`. Длина обучения 160 токенов.

Сам по себе он слабый: 0.74 PR-AUC на ручных парах, то есть примерно уровень
недообученной модели. Ценность в другом — дообучение с него даёт +0.0215
против дообучения с голого `deepvk/RuModernBERT-base`. Шесть часов на RTX 5070 Ti.

Стартовать так: `--init members/darksteeld/models/rumodernbert_llm_pretrain`.

**Важное ограничение.** Претрен видел только 160 токенов, а медианная пара в
корпусе — 260, то есть обрезалось 81.4% пар и до модели доживало 55.4% текста.
Похоже, именно поэтому длина при дообучении насыщается: 224 -> 320 даёт +0.0023,
а 320 -> 1024 не даёт ничего. Модель не умеет пользоваться контекстом, которого
не видела. Это подтвердилось замером: дайте ему вход в 512 токенов, и он станет
хуже, 0.7148 против 0.7331. Ограничение снято претреном ниже — берите его.

## `rumodernbert_llm_pretrain_512/`

То же самое, но длина 512 и голова сразу на один логит. Одна эпоха по тем же
11.19M пар, зеркальная аугментация, группировка по длине. 16 часов на RTX 5070 Ti.

**Это сильнейший претрен из всех, что у нас есть**, и он ценен сам по себе, а не
только как старт для дообучения. На публичном лидерборде **0.51169 в одиночку** —
больше, чем у нашей дообученной модели длины 224 (0.50603), и почти вровень со
стеком из двух моделей (0.51245). Притом что человеческих меток он не видел ни
одной.

Замер на 20 тысячах ручных пар, честный по построению — все претрены этих меток
не видели:

| претрен | вход | PR-AUC |
| --- | ---: | ---: |
| претрен 160 | 160 | 0.733139 |
| претрен 160 | 512 | **0.714784** |
| **претрен 512** | 512 | **0.748740** |

Вторая строка важнее первых двух: короткому претрену длинный вход **вредит**.
Модель не умеет пользоваться контекстом, которого не видела, и это объясняет,
почему при дообучении длина переставала помогать после 320.

Осторожно с локальными числами: локально этот претрен на 0.116 слабее нашей
дообученной модели, а на лидерборде сильнее её. Подробности в `../ops/README.md`.

Тексты — **простые** (`имя | категория | атрибуты`), блока `@@ сравнение` он не
видел. Кормить его prio-текстами нельзя.

## `rumodernbert_len320_fold_0{1,2,3,4}/`

Четыре фолдовые модели лучшей на сегодня конфигурации: дообучение с претрена
выше, длина 320, Adan lr 1e-4, две эпохи, обрезка хвостов атрибутов, выведенные
транзитивным замыканием пары исключены. Голова на два логита. fp16.

Каждая обучена на трёх фолдах и не видела своего:

| модель | не видела | PR-AUC на ней |
| --- | --- | ---: |
| `fold_01` | fold_01 | 0.861818 |
| `fold_02` | fold_02 | 0.869257 |
| `fold_03` | fold_03 | 0.863892 |
| `fold_04` | fold_04 | 0.864569 |
| **среднее** | | **0.864884** |

Макро по 20 категориям — 0.816898. Контроли: `ce_priodistill` 0.851713,
ансамбль из семи моделей 0.856377.

Предсказания этих же моделей на своих held-out фолдах лежат в
`../preds/rumodernbert_oof.parquet` — их можно блендить со своими без риска
утечки.

### Как сложить их в одну модель

    python ops/soup_models.py \
        --models members/darksteeld/models/rumodernbert_len320_fold_0{1,2,3,4} \
        --out runs/soup

Усреднение весов законно потому, что все четыре ушли из одной точки — включая
голову классификатора — и разошлись мало: медианное относительное расхождение
0.0414. Скрипт печатает эту величину; если она окажется большой, супу верить
нельзя. Суп из этих четырёх внутри посылки, набравшей 0.5124 на публичном
лидерборде (в паре с `student e3 len384` от dzkhomidov, веса 0.75 и 0.25).

**Качество супа локально не проверяется.** Вместе эти модели покрывают все
четыре фолда, поэтому любая оценка супа на размеченных парах внутривыборочная.
У нас так получалось 0.908 против честных 0.863 — на этом легко обмануться,
ровно так же, как раньше с выложенной rubase (0.8858 против 0.851713).

### Инференс

Тексты собираются как в `container/mb_stack320/run.py`: prio-порядок атрибутов,
блок `@@ сравнение`, обрезка имени по первому `' | '` и адаптивная обрезка
хвостов атрибутов под 320 (`src/pair_budget.py`). Совпадение с обучающими
текстами проверено побайтово. Расхождение здесь разводит train с test.
