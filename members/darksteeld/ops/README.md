# RuModernBERT кросс-энкодер: воспроизведение

Всё, что нужно, чтобы получить нашу модель с нуля. Числа в таблицах — честный
OOF: каждая фолдовая модель проверена на фолде, которого не видела, и меряется
только на ручных парах, чтобы сравниваться с `ce_priodistill` (0.851713).

## Результаты

| конфигурация | среднее по фолдам | макро по 20 категориям |
| --- | ---: | ---: |
| `ce_priodistill` (dzkhomidov, контроль) | 0.851713 | 0.799403 |
| ансамбль из 7 моделей (dzkhomidov, контроль) | 0.856377 | 0.804974 |
| rubert-base + LLM-претрен, AdamW, длина 224 | 0.855566 | 0.805135 |
| RuModernBERT + LLM-претрен, Adan 1e-4, длина 224 | 0.863304 | 0.813467 |
| **RuModernBERT, длина 320, обрезка атрибутов** | **0.864884** | **0.816898** |

Свип шага у Adan на длине 224: 5e-5 даёт 0.861031, 1e-4 даёт 0.863304,
2e-4 даёт 0.862420. Оптимум внутри сетки, расширять её незачем.

Отдельно измеренные эффекты, каждый устойчив на 4 фолдах из 4:

| изменение | среднее | макро |
| --- | ---: | ---: |
| длина 224 -> 320 | +0.002338 | +0.004788 |
| обрезка хвостов атрибутов вместо конца пары (при длине 224) | −0.000758 | −0.001357 |
| выведенные транзитивным замыканием пары в обучении | −0.001594 | — |

## Данные

`llm_texts.parquet` — справочник `id -> "имя \| категория \| атрибуты"` по всем
12.38M товаров. Собирается построчными группами, иначе не хватает памяти:

    python ops/build_llm_texts.py --items data/raw/items.parquet \
        --out llm_texts.parquet

`hand_pairs_distill_aug.parquet` — обучающие пары с prio-текстами и мягкой
целью `0.7 * final_stack_all + 0.3 * hard`:

    python src/build_distill_pairs.py --oof members/dzkhomidov/preds/all_model_predictions_oof.parquet \
        --items data/raw/items.parquet --teacher final_stack_all --alpha 0.7 \
        --out hand_pairs_distill_aug.parquet

Текст пары: `имя | категория | атрибуты` в порядке бренд/модель/артикул/цвет,
плюс блок `@@ сравнение: цвет=...; артикул=...`. У фэшн-категорий выбрасываются
атрибуты размера. **Имя обрезается по первому `' | '`** — это дефект `run_v4`
у dzkhomidov, воспроизведён намеренно: инференс делает так же, и расхождение
здесь развело бы train с test.

## Шаг 1: претрен на разметке LLM

11.19M мягких пар, одна эпоха. Даёт +0.0215 против обучения без него.

    python ops/pretrain_llm.py --texts llm_texts.parquet --pairs matches_llm.parquet \
        --model deepvk/RuModernBERT-base --out ckpt/mb_llm \
        --epochs 1 --max-len 160 --bs 128 --workers 16 --lr 5e-5 \
        --compile --pad-multiple 32 --save-every 2000

6 ч 10 мин на RTX 5070 Ti, 504 пар/с. Чекпоинт — 576 МБ.

## Шаг 2: дообучение по фолдам

    python ops/train_distill.py --data hand_pairs_distill_aug.parquet \
        --model deepvk/RuModernBERT-base --init ckpt/mb_llm \
        --out runs/budget320 --stage folds --epochs 2 \
        --bs 48 --eval-bs 48 --max-len 320 --workers 16 \
        --optimizer adan --lr 1e-4 --compile --pad-multiple 32 \
        --drop-closure --budget-attrs --save-models

`--drop-closure` обязателен: выведенные замыканием пары измеренно вредят.

## Шаг 3: усреднение весов фолдовых моделей

    python ops/soup_models.py --models runs/budget320/model_fold_0{1,2,3,4} \
        --out runs/budget320_soup

Законно потому, что все четыре дообучались из одного чекпоинта вместе с головой
классификатора и разошлись мало: медианное относительное расхождение 0.0414.
Скрипт печатает эту величину — если она окажется большой, супу верить нельзя.

**Проверить качество супа локально невозможно.** Он собран из моделей, вместе
покрывающих все фолды, поэтому любая оценка на размеченных парах будет
внутривыборочной. У нас такое число получалось 0.908 против честных 0.863 —
показывать его как качество нельзя.

## Сравнение прогонов

    python ops/compare_arms.py --runs runs/A runs/B \
        --data hand_pairs_distill_aug.parquet --items data/raw/items.parquet

Печатает PR-AUC по каждому фолду, среднее, макро по 20 категориям и парные
разности. **Смотреть надо на устойчивость знака по фолдам, а не на среднее:**
шумовой пол пайплайна около 0.0003, и разница того же порядка ничего не значит,
даже если выглядит убедительно.

## Ускорение обучения

| приём | эффект |
| --- | --- |
| `--compile --pad-multiple 32` | +59% на претрене, +48% на фолдах |
| `--length-buckets` | −38% вычислений: батчи из пар близкой длины |
| `GradScaler` отключён | при bf16 бесполезен, стоит синхронизации каждый шаг |

`torch.compile` может не собраться из-за отсутствия заголовков python3.12:
Triton компилирует C-расширение с `#include <Python.h>`. Сообщение об ошибке при
этом указывает на `libcuda` и уводит в сторону. Без прав root лечится так:

    apt-get download libpython3.12-dev python3.12-dev
    dpkg-deb -x <файл>.deb ~/pyinc
    export CPATH=$HOME/pyinc/usr/include/python3.12:$HOME/pyinc/usr/include

## Что измерено и не сработало

- **Обрезка хвостов атрибутов вместо конца пары.** Блок сравнения при глобальной
  обрезке выживает лишь в 7.5% обрезанных пар, адаптивная обрезка сохраняет его
  в 100%. И тем не менее качество падает на 0.00076, устойчиво на 4 фолдах из 4:
  модель извлекает из длинного хвоста атрибутов больше, чем из явного вердикта.
- **Пары из транзитивного замыкания в обучении** — −0.001594, отрицательно на
  всех фолдах.
- **Доразметка спорных пар** — три независимых измерения, все внутри шумового
  пола.
