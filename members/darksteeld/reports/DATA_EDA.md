### 3.1 Согласованность LLM ↔ ручных меток: НЕ ИЗМЕРИМА на парах

Пересечение по ключам пар = **0 строк** — потому что пересечение по товарам = 0 по
построению (организаторы разнесли вселенные). Калибровочная кривая LLM→hand на общих парах
невозможна. Следствия:

1. **Плюс:** обучение на всём `matches_llm` не может протечь в фолды ручной валидации —
   ни один товар не общий. Никаких ограничений на использование LLM-пар при обучении.
2. **Минус:** сдвиг LLM-меток относительно ручных можно оценить только моделью
   (train-on-LLM → eval-on-hand-folds), это отдельный преригистрированный эксперимент.

## 7. Следствия для дизайна

1. **Фолды группируются по компонентам связности ручного графа** — дёшево (max группа 31
   пара) и закрывает 9.5% пар с общими товарами. Контракт: `validation/README.md`.
2. **`matches_llm` — леик-безопасный доп. train** относительно ручных фолдов (пересечение
   товаров = 0). Его сдвиг к ручным меткам неизвестен и требует модельного эксперимента.
3. Метрика вероятно пул («total»), но прецедент 2024 — макро-по-категориям; evaluate
   считает обе агрегации с первого дня (разброс prior по категориям 0.073–0.562).
4. Тексты короткие: name ~58 симв. — сигнал в основном в name + attributes; описаний в
   данных нет вообще (только name/attributes/category), §12.2 FAMILY_MATCHING неактуален
   в части description.
